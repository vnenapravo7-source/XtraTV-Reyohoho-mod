# Сборка и выпуск

## Архитектуры и проверка

JDK 21, Android SDK 37. `-PtargetAbi=` принимает только `armeabi-v7a`, `arm64-v8a`, `x86`, `x86_64`. Один запуск создаёт APK только для одной архитектуры.

```sh
./gradlew :app:testDebugUnitTest :app:assembleOptimized -PtargetAbi=armeabi-v7a
```

На Windows используйте `gradlew.bat`. При ошибке локального сокета JDK задайте существующий короткий временный каталог в `JAVA_TOOL_OPTIONS`: `-Djava.io.tmpdir=C:/jtmp -Djdk.net.unixdomain.tmpdir=C:/jtmp`.

`optimized` сохраняет package ID и подпись текущих тестовых сборок. Публичный `app/debug-keystore.jks` унаследован от upstream: это ключ разработки, не приватный ключ публикации.

## Подписанный релиз

Для локального `assembleRelease` задайте `RELEASE_KEYSTORE_PATH`, `RELEASE_KEYSTORE_PASSWORD`, `RELEASE_KEY_ALIAS`, `RELEASE_KEY_PASSWORD`. Без ключа release APK остаётся неподписанным.

Для Actions сохраните четыре секрета:

| Секрет | Значение |
|---|---|
| `RELEASE_KEYSTORE_BASE64` | JKS в base64 |
| `RELEASE_KEYSTORE_PASSWORD` | Пароль хранилища |
| `RELEASE_KEY_ALIAS` | Имя ключа |
| `RELEASE_KEY_PASSWORD` | Пароль ключа |

Ключи и пароли не коммитятся. Workflow `Draft release` запускается вручную для тега текущей версии, строит четыре подписанных APK, проверяет их подпись и архитектуру, добавляет SHA-256 и создаёт черновик GitHub Release. Публикация черновика выполняется отдельно после проверки. Обычный push/PR создаёт только тестовые артефакты.

`release` имеет package ID без `.debug`, отличный от тестовых сборок. Обновление между ними не переносит аккаунты автоматически; обновления внутри одного package ID с той же подписью сохраняют данные.

## Совместимость данных

Закладки и подписки сохранены. Исторические Room-сущности офлайн-видео оставлены для совместимости базы; UI, импорт файлов, службы загрузок и вход в офлайн-плеер удалены. Старые локальные файлы автоматически не удаляются. Онлайн-DVR при доступности VOD сохранён.

На реальном устройстве проверяются фокус, ручное подключение/отключение чата и фактическое разрешение видео. Для проверки adblock нужна рекламная вставка: обычный просмотр не подтверждает блокировку всех видов рекламы.
